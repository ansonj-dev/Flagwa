# Data Sources, Provenance & Attribution

FLAGWA combines satellite measurements with optional contextual datasets. These inputs have different scientific roles, spatial/temporal resolutions and reuse terms. A layer being technically ingestible does not make it suitable for every study.

## Source roles

| Source | Intended role in FLAGWA | Important caveat |
|---|---|---|
| NASA/ASF NISAR collections | Primary SAR observations and product metadata | Check actual product, maturity, acquisition geometry, layers, masks and baseline |
| NASA Earthdata Login | Authenticated access to restricted NISAR downloads | Credential/access service, not a measurement source |
| ISRO/NRSC Bhoonidhi | NISAR S-band collection access and product information | Separate portal/programmatic authorisation; portal login does not prove API permission |
| JRC Global Surface Water | Historical water occurrence/permanent-water context | Temporal baseline; not a current water observation for every acquisition |
| ESA WorldCover | Land-cover context | Product epoch, class accuracy and reuse terms matter |
| Copernicus DEM / SRTM | Terrain context | Resolution, vertical datum, microtopography and licence/reuse must be checked |
| NASA GPM IMERG | Rainfall context | A catalogue record is not proof that a raster/time series was acquired and ingested |
| WorldPop | Population context | Temporal estimate, grid resolution and coverage must be reviewed |
| OpenStreetMap | Roads, buildings and places | Community-edited completeness, age and ODbL attribution requirements |
| Optical imagery | Independent visual/land-cover evidence | Cloud, date, resolution, sensor and processing differences |

Provider access can change. Check current endpoint status and dataset metadata for the study/run rather than using this table as a live availability statement.

## Provenance fields to retain

For every imported dataset or scientific input, preserve as much as the source makes available:

- provider and dataset/product identifier;
- source URL or stable catalogue reference;
- source product version, collection or release;
- acquisition/observation time and processing/update time;
- download/ingest time;
- spatial footprint, CRS, resolution and coverage;
- measured variable, units, scale factor and nodata/quality semantics;
- processing lineage and software/method version;
- licence, attribution and redistribution restrictions;
- checksum or integrity identifier for stored assets;
- quality flags, known limitations and review state.

The actual context registry schema and API contract remain authoritative. Do not manufacture metadata absent from a provider.

## Scientific separation of evidence

A useful interpretation keeps these categories distinct:

1. **Primary observation:** NISAR pixels/layers and acquisition metadata.
2. **Derived measurement:** a value or class generated by a named algorithm from explicit inputs.
3. **Context:** water, land cover, terrain, rainfall, population or infrastructure.
4. **Supporting evidence:** optical scenes, event records, local observations or field data.
5. **Hypothesis:** a possible physical explanation for the observation.
6. **Validation decision:** a documented assessment against independent evidence.

Context must not silently become ground truth. A historical permanent-water layer is not proof that a pixel was wet on the SAR acquisition date. An optical scene acquired weeks later is not a simultaneous reference. A road/building inventory may be incomplete.

## Citation and attribution

When publishing a map, report, screenshot or export:
- cite exact NISAR scene/product identifiers and acquisition dates;
- cite contextual dataset name, version/collection and access date;
- provide source URLs where possible;
- retain attribution required by each data provider;
- state FLAGWA algorithm/method version and relevant parameters;
- label imagery used for visual context separately from measured SAR layers;
- check source licences before redistributing the underlying data.
